# rootiest-fyi

Source for [rootiest.fyi](https://rootiest.fyi), the index of Rootiest's public docs and shares, and for
the [Rootiest Mail guide](https://email.rootiest.fyi).

The site is plain static HTML generated by a small Python script (standard library only). It runs no
JavaScript and loads nothing from other sites. The only outside requests are the site icons on the hub,
which come from [icons.rootiest.fyi](https://icons.rootiest.fyi).

## Layout

| Path | What it is |
|---|---|
| `sites.yaml` | The catalog: every site on the hub, with its title, description, icon and category |
| `content/email/` | The Mail guide's pages, as HTML fragments |
| `site/` | The web root. Everything in it is published, nothing outside it is |
| `site/assets/site.css` | Styles: Catppuccin Latte (light) and Mocha (dark), following the system setting |
| `site/email/shots/` | The guide's screenshots, added by hand |
| `scripts/build.py` | Generates the pages into `site/` |
| `scripts/check.py` | Checks `site/`: up to date, no broken links, no third-party scripts |
| `scripts/sitegen/` | The generator: catalog reader, guide renderer, HTML building blocks |
| `tests/` | Tests, with a small fixture guide in `tests/fixtures/` |

Every `.html` file in `site/` and `site/email/assets/site.css` are generated. Never edit them by hand:
edit the sources and rebuild. Everything else in `site/` (favicons, screenshots) is kept by hand.

## Build and check

```sh
python3 scripts/build.py          # regenerate site/
python3 scripts/check.py          # what CI and the publish job run
./tests/run-tests.sh              # the tests, then the check
python3 scripts/check.py --online # also fetch every catalog URL and icon
```

Preview locally with any static server, for example `python3 -m http.server -d site 8000`. The guide is
then at `http://localhost:8000/email/`.

## Adding a site to the hub

Add an entry to `sites.yaml` and rebuild. The file's header lists the fields. It's written in a strict
subset of YAML so the build needs no extra Python packages: if a value has `: ` or ` #` in it, or starts
with a special character, put it in double quotes. The build stops and names the line when something
doesn't fit. Run `python3 scripts/check.py --online` to make sure the new URL and its icon load.

Every site on `rootiest.fyi` should be in the catalog. A check in the private infrastructure repo compares
it with the list of `.fyi` sites there and reports any that are missing.

## Writing the Mail guide

Each page is a fragment in `content/email/`. `index.html` is the guide's first page, and every other
`<slug>.html` becomes `email/<slug>/`. A page starts with three comments:

```html
<!-- title: Set up mail on your phone -->
<!-- description: One sentence for search results and link previews. -->
<!-- order: 20 -->
```

The pages are listed by `order`. The build adds the page's title as its `<h1>`, unless the fragment has an
`<h1>` of its own.

Links between pages are relative to the page as it's published: from the first page write
`href="phone/"`, from any other page `href="../phone/"`. Keep every link and image relative, because the
guide is served at both `email.rootiest.fyi/` and `rootiest.fyi/email/`. `scripts/check.py` fails on a
link that would only work at one of them.

### Screenshots

```html
<figure class="shot" data-shot="phone-imap">
  <img src="../shots/phone-imap.png" alt="The IMAP settings screen">
  <figcaption>Server settings for IMAP.</figcaption>
</figure>
```

The image goes in `site/email/shots/<id>.png`. Its `src` is relative to the page: `shots/<id>.png` on the
first page, `../shots/<id>.png` everywhere else (the build accepts either form on any page and writes the
right one). Until the file exists, the page shows a placeholder with the alt text and the shot's id, and
the build and check list it as pending without failing.

## Deployment

Pushes to `main` on [git.rootiest.dev](https://git.rootiest.dev/rootiest/rootiest-fyi) run
`.github/workflows/pages.yml`, which checks the site and publishes `site/` to the Rootiest edge servers'
static web root (`pages/rootiest-fyi`), live within a few minutes on both edges. Caddy serves that folder
at `rootiest.fyi`, and its `email/` folder at `email.rootiest.fyi`. `docs.rootiest.fyi` and
`www.rootiest.fyi` redirect to `rootiest.fyi`.
